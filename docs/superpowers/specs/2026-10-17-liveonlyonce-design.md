# LiveOnlyOnce 设计文档

日期：2026-10-17
仓库：https://github.com/foXerw/liveonlyonce
首个实例域名：liveonlyonce.me

## 意图与动机

用户在前几天意识到"人只能活一次，要过得精彩一点"，于是想建一个网站，作为对自己人生的公开约定与纪念：展示人生旅途中值得纪念的瞬间，随着时间推移不断生长。它既是给别人看的（所有人，包括未来的自己回看），也是一个**通用开源产品**——任何人都可以下载部署，展示自己的人生。liveonlyonce.me 是这个产品的第一个实例。

页面的动人之处在于"精彩才刚开始"：现在内容不多（主要是青甘大环线的自驾照片，未来会有新工作、婚礼、老家、电影感想、随感文字等），设计不应假装内容丰富，而应把"少"变成叙事的一部分，让每个后来添加的瞬间都像往一面正在生长的墙上又钉了一张照片。

## 内容特质（核心设计约束）

内容天生杂乱，但展示必须自动地漂亮。一条"瞬间"可能是以下任意一种：

- 一次旅行：十几到几十张照片 + 一段长感想（青甘大环线：雪山、青海湖、公路）
- 一部电影：一张海报 + 个人感想
- 一张照片：例如新工作的工号牌
- 纯文本：某天的有感而发，一大段话，可能一张图都没有

## Goals

1. 浏览体验自然沉浸，布局与 UI 达到专业设计师水准（"可以获奖"的目标气质）
2. 黑色为底 + 蓝色家族为主色（蓝色是用户最喜欢的颜色；具体色卡以视觉稿与用户共同选定，标准是"看到就觉得是它"）
3. 中英双语全站，默认中文，可切换，记住偏好
4. 内容维护极简：磁盘真实文件夹 + 口令保护的上传页面双轨，新增内容永远不碰代码
5. 通用可部署：他人 clone → 装依赖 → 起服务即可换成自己的内容
6. 首页时间线之上有一个克制的开场宣言：**隐晦、不直白**，让人一眼看不太懂但心里被挠一下，进而反思自己也要活得精彩（具体文案与视觉稿一起打磨）

## Non-goals

- 多用户体系、注册、个人账号（管理入口最多是一个口令）
- 评论、点赞等访客互动
- 博客式富文本编辑器、分类、标签、归档检索
- 移动端原生应用
- "关于我"的长篇个人介绍页（只要极小的"关于此站"一两句话 + 页脚 + 邮箱联系方式）

## Anti-goals（技术上跑通也算失败的情形）

- 看起来像模板站（通用卡片网格、开箱即用主题的味道）
- 口号式直白（"活得精彩！"式喊话）、倒计时/已活天数这类跳动的自我感动元素（用户明确否决）
- 内容少时页面显得空荡寒酸，或内容多时杂乱无章
- 新增一条回忆需要改代码、重新构建或懂开发

## 已定的技术方案

以下由助手权衡选定（用户授权："现代化成熟技术栈，你自己权衡"）：

- **框架**：Next.js（App Router）+ React，前端展示与后端 API 同一应用
- **样式**：Tailwind CSS；**动效**：Framer Motion
- **图片**：sharp 生成缩略图/占位图；原图存磁盘内容目录
- **无数据库**：元数据全部写在每条瞬间的描述文件里，备份 = 拷贝文件夹
- **部署**：明确**不用 Docker**（用户否决）。Linux 服务器上 Node 直接运行，pm2（或 systemd）守护，前置 nginx/caddy 反向代理域名；README 给出完整部署说明与反代配置示例

## 内容模型

- 内容目录（路径可配，如 `content/`，或独立于代码仓库的内容目录）下每条瞬间 = 一个子文件夹：`NNNN-MM-DD-短slug/`，内含图片文件 + 一个 `moment.yaml`（或 json）描述文件
- 描述字段：日期、中文标题、英文标题、中文描述、英文描述、（可选）置顶标记、（可选）地点等轻量元信息
- **类型不手填，自动推断**：多图 → 相册型；单图 → 特写型；零图 → 文本型；竖版海报图也可由宽高比自动识别参与版式选择
- 页面排序自动按日期倒序（最新在前），按年份分组；置顶项可被首页 hero 区采用

## 页面结构

### 首页

1. **Hero 区**：隐晦双语宣言 + 主题氛围（黑底、蓝色微光/渐变，克制）。无数字计数器
2. **人生时间线**：纵向中轴线，按年份分段；每个节点是**按内容类型自动生成**的预览卡——旅行为宽幅大图卡、电影为竖版海报卡、单图为方卡、纯文本为排版精致的语录卡
3. 首页内容少时靠排版、留白与叙事元素（如"故事刚刚开始"式的收尾处理，具体呈现待视觉稿）保持质感，不显得空

### 详情页（点击时间线节点进入）

按内容自动选择叙事方式：

- 多图旅行：沉浸式滚动叙事（大图逐段浮现 + 感想文字）
- 单图/海报：大特写 + 感想文字
- 纯文本：专注阅读的文章版式
- 极简单的单图瞬间可以只在首页灯箱放大，不必有独立页面（builder 裁量）

### 其他

- 极小"关于"：一两句说明此站是什么（通用产品必需）；页脚；邮箱联系方式（可配置）
- zh/en 切换控件，全站文案与内容双语覆盖；内容缺少某语言版本时的回退策略由 builder 定（如回退到另一语言）

## 管理与发布

- **双轨同构**：往内容文件夹手工放文件夹、或通过管理页面上传，最终落到同一数据源；应用启动时/定时扫描内容目录
- **管理页**：`/admin`，单一口令保护（环境变量 ADMIN_KEY），无账号体系。能力：新建瞬间（选日期、传多张图、填中英标题描述、设置顶）
- 防滥用：口令校验 + 上传大小/频率限制；HTTPS 由反向代理层负责
- 编辑既有瞬间：支持（改描述文件/重新上传同样走这两轨）

## 视觉设计方向（待视觉稿确认的部分）

- 黑底 + 蓝色家族。候选方向（供视觉稿展开）：深邃夜蓝底、钴蓝、电光蓝、冰青——最终色卡由用户在浏览器视觉稿中挑选确认
- 设计过程将调用 frontend-design 技能，追求编辑级排版：大留白、克制的动效、讲究的中英文字体搭配（候选：思源黑体/宋 + 一款现代衬线西文，具体由设计阶段定）
- 视觉得分点：时间线的"生长感"、类型自适应卡片、隐晦宣言的开场气质

## 留给 builder 的决定

- 项目目录结构、代码组织、组件拆分
- 图片管线细节（尺寸档位、blur placeholder、懒加载）
- SEO/分享（meta、og:image 用瞬间首图）、无障碍（对比度达标，蓝色在黑底上的可读性）
- 性能：首页时间线随内容增长的分页/懒加载策略
- pm2 ecosystem 配置、README（含通用部署指南与配置项清单）
- 内容目录是否支持 git submodule 分离个人内容（通用产品的好做法，builder 裁量）

## 未决项（需与用户视觉会话共同定）

1. 开场宣言的具体文案（中文 + 对应英文）
2. 蓝色色卡终选
3. 时间线与动效的具体呈现样式（预览效果图确认，含 A/B/C 布局在详情页的落地效果）
